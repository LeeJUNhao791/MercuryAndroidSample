# PRD 深度分析（眼镜 AR 项目版）

## 使用场景
拿到眼镜 AR 项目的需求文档（PRD / 需求描述）后，在开始写代码之前，运行此 Prompt。

## 输入参数
- `$PRD_CONTENT`：产品需求文档的完整内容

## Prompt 正文

---

你是 RayNeo AR 眼镜项目的资深 Android 架构师。请从**三个角色视角**对以下 PRD 进行深度分析：

## PRD 内容
$PRD_CONTENT

---

## 角色一：挑剔的技术评审（找漏洞）

请列出 PRD 中未明确定义的行为和边界 case，每个遗漏标注优先级：
- **P0**（会阻塞开发，必须在开发前确认）
- **P1**（会导致线上 Bug，产品需给出明确结论）
- **P2**（体验瑕疵，可接受当前状态或延后处理）

对每个遗漏，你必须**给出你的建议方案**，不只是指出问题。

**眼镜 AR 专项检查：**
- 是否说明了哪些界面显示在眼镜端、哪些在手机端（还是只在眼镜端）
- 触摸板手势是否完整覆盖所有交互场景（点击、双击、滑动方向）
- **X2/X3 手势差异**：是否标注了哪些手势只在 X3 支持（`SlideUpwards`/`SlideDownwards`）
- 焦点导航顺序是否明确定义（第一个焦点落在哪个元素）
- 语音交互与触摸板交互的优先级是否说明
- 横屏（landscape）布局是否已考虑
- 双目显示（左右眼同步）是否有特殊处理需求
- **Camera 需求**：是否需要 X3 的 VGA 摄像头进行空间定位
- **Audio 需求**：MIC 录音模式是否需要区分 X2/X3 实现

## 角色二：数据模型设计师（建结构）

请从 PRD 中提取：
1. 所有实体（Entity）和它们的字段、类型、约束
2. 实体之间的关系（1:1、1:N、N:N）
3. 标注哪些字段是 PRD **显式提到**的，哪些是你**推断补充**的

为每个实体生成 Kotlin data class 初稿，放在 `domain/model/` 下。

## 角色三：状态机工程师（理流程）

请提取核心业务流程的状态转换，每个状态标注：
- **触发条件**：什么操作会进入这个状态
- **执行动作**：系统需要做什么（特别关注眼镜端的焦点变化、视图切换）
- **目标状态**：执行完成后流转到哪个状态

**眼镜 AR 专项状态检查：**
- 焦点获取（reqFocus）和释放（releaseFocus）的时机是否正确
- 页面切换时的焦点状态是否需要保存和恢复
- RecyclerView 滑动时焦点位置是否需要重置

标注哪些转换路径 PRD 没有覆盖，需要向产品确认。

## 输出要求

1. 使用结构化 Markdown 格式
2. 遗漏清单按 P0 → P1 → P2 优先级排序
3. 每个模块给出你的置信度（**高 / 中 / 低**），并标注需要向产品确认的点
4. 生成的数据模型放在代码块中（```kotlin ...```）
5. 状态机用表格 + Mermaid 流程图描述
6. 明确标注哪些功能需要在眼镜端（BaseMirrorActivity）和手机端（BaseEventActivity）分别实现

---

## 分析完成后，请给出

1. **技术 Spec 初稿**（可在开发时直接使用的结构化文档，标注眼镜端/手机端）
2. **开发阻塞清单**（P0 问题，在开始编码前必须解决）
3. **眼镜端 UI 评估清单**（哪些页面用 BaseMirrorActivity、焦点如何组织）
4. **建议的接口草稿**（REST API 或 SDK 调用，用 Kotlin data class 表示）
